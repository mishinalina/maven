## Build Commands

This project bootstraps itself (Maven building Maven). First-time setup requires Ant:

```bash
export M2_HOME=$HOME/apps/maven/apache-maven-3.0-SNAPSHOT
ant
```

Once a Maven distro is available, the standard build is:

```bash
mvn install                          # build and install all modules
mvn install -DskipTests              # skip tests
mvn test                             # run all tests
mvn test -pl maven-core              # run tests for a single module
mvn test -pl maven-core -Dtest=LifecycleExecutorTest   # run a single test class
mvn test -pl maven-core -Dtest=LifecycleExecutorTest#testMethod  # single test method
```

Test output is redirected to files by default (`maven.test.redirectTestOutputToFile=true` in root pom).

## Module Overview

| Module | Purpose |
|---|---|
| `maven-core` | Core execution engine: lifecycle, plugin management, project dependency graph |
| `maven-model` | POM model classes, generated by Modello from `maven-model/src/main/mdo/maven.mdo` |
| `maven-model-builder` | Multi-phase POM construction: raw parse → inheritance → interpolation → validation |
| `maven-settings` | `settings.xml` model and builder |
| `maven-artifact` | `Artifact` abstraction, local/remote repository interfaces, resolution contracts |
| `maven-plugin-api` | `Mojo` interface and annotations — the public API for plugin authors |
| `maven-embedder` | CLI entry point (`MavenCli`) and embedding API |
| `maven-compat` | Maven 2.x compatibility shims; avoid adding new code here |
| `maven-repository` | Higher-level repository abstractions built on maven-artifact |
| `apache-maven` | Distribution assembly only — no production code |

## Architecture

### Component Model: Plexus IoC

All components use the Plexus DI container (not Spring/Guice). Components are declared with `@Component` and dependencies injected with `@Requirement`. Component descriptors are generated at build time from annotations and stored in `META-INF/plexus/components.xml`. When adding a new component, the annotation is the source of truth; do not edit descriptor XMLs manually.

### Request Execution Flow

```
MavenCli.doMain()
  → MavenCli.execute()          (builds MavenExecutionRequest, initializes PlexusContainer)
  → DefaultMaven.execute()      (populates request, collects projects, creates MavenSession)
  → LifecycleStarter.run()      (computes build order via ProjectSorter, drives the reactor)
  → LifecycleModuleBuilder      (executes one project: resolves lifecycle → plugin goals → MojoExecutor)
  → MojoExecutor.execute()      (configures and runs a single Mojo in its isolated ClassRealm)
```

`MavenSession` is the shared mutable state passed through the entire execution. `MavenExecutionRequest` is immutable input; `MavenExecutionResult` collects output.

### POM Build Pipeline (`maven-model-builder`)

`DefaultModelBuilder` processes a POM through sequential phases:
1. **Raw model** — parse XML via `ModelProcessor`
2. **Profile activation** — select active profiles
3. **Inheritance** — merge parent POMs (resolved recursively)
4. **Interpolation** — resolve `${...}` expressions
5. **Plugin management injection** — apply `<pluginManagement>` defaults
6. **Validation** — enforce model constraints

`ModelBuildingRequest` / `ModelBuildingResult` are the in/out types; `ModelBuildingListener` hooks into phase transitions.

### Lifecycle → Plugin Goal Resolution

The lifecycle executor in `maven-core/src/main/java/org/apache/maven/lifecycle/internal/` maps lifecycle phases to plugin goals:

1. `LifecycleTaskSegmentCalculatorImpl` splits the command line into `TaskSegment`s (lifecycle phases vs. direct goal invocations).
2. `LifecycleExecutionPlanCalculatorImpl` expands each segment into an ordered `MavenExecutionPlan` of `MojoExecution`s by consulting lifecycle-to-plugin mappings (from `<packaging>`-specific lifecycle bindings) and the POM's `<build><plugins>`.
3. `LifecyclePluginResolver` resolves plugin versions from `<pluginManagement>`.
4. `MojoDescriptorCreator` loads `MojoDescriptor`s from plugin JARs via `MavenPluginManager`.

Parallel builds (`-T` flag) use `LifecycleWeaveBuilder` / `LifecycleThreadedBuilder` with a `ConcurrencyDependencyGraph`.

### Plugin Isolation

Each plugin gets its own `ClassRealm` (child-first `URLClassLoader`), populated with the plugin artifact and its resolved dependencies. The core API packages are imported from the container's realm. `DefaultPluginRealmCache` caches realms keyed by plugin GAV + dependencies to avoid redundant classloading.

### Testing Conventions

Tests in `maven-core` extend `AbstractCoreMavenComponentTestCase`, which spins up a lightweight Plexus container and loads components from the classpath. Test POMs live under `src/test/resources/` and are loaded by helper methods on the base class. JUnit 3.x style (`extends TestCase`) is used throughout — do not introduce JUnit 4+ annotations in existing test classes.
